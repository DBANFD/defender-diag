Piloting the Intune STIG audit baseline

Measure Windows configuration gaps without confusing audit results with enforcement.

Know what the baseline does

Intune's STIG audit baseline is a read-only assessment of Windows device configuration against a DISA Security Technical Implementation Guide. It produces per-setting and per-device results; it does not configure settings or make a device compliant. The initial Microsoft Windows 11 STIG SCAP Benchmark is Version 2, Release 7 with 197 rules and a benchmark date of 5 January 2026. Microsoft STIG audit baseline guidance.

The feature was listed in Intune service release 2610 during the week of 26 October 2026. Microsoft says Intune monthly updates roll out gradually, so availability can differ by tenant. Intune what's new.

Check prerequisites

  • Commercial or GCC High tenant.
  • Intune Advanced Analytics licensing.
  • Windows 10 or Windows 11 devices enrolled in Intune.
  • For co-managed devices, Device configuration workload set to Pilot Intune or Intune.
  • An Intune role with Organization Read and Security baselines Assign, Create, Delete, Read, and Update. Report viewers also need Device configurations View Reports and applicable scope tags.

Windows 11-specific rules assigned to Windows 10 can report Not applicable. Confirm platform mix before treating that status as an exception.

Run a controlled pilot

  1. Create a small device group that represents supported hardware, OS versions, management states, and existing security baselines.
  2. In Intune admin center, go to Endpoint security → Security baselines and create a profile from Microsoft Windows 11 STIG SCAP Benchmark.
  3. Assign only the pilot group. The audit profile evaluates all rules; individual STIG settings can't be selected or modified.
  4. Allow at least 24 hours for initial results. A temporary Error state during initial reporting doesn't by itself prove a failed benchmark check.
  5. Use the profile's Audit report, not standard policy check-in reports, for per-setting and per-device results.

Interpret results

StatusInterpretation
Pass / FailThe current device value did or did not match the audited rule at evaluation time.
Not applicableThe rule doesn't apply to that device; often expected across mixed OS versions.
UnknownThe device has not reported a result yet.
ErrorEvaluation or data retrieval failed; investigate separately from a configuration failure.
ConflictA conflicting policy was detected for the setting.

Results are not real time and can lag one or two device check-in cycles. Record the baseline version, report generation time, last device check-in, and target group with exported evidence.

Separate assessment from remediation

Prioritize failed CAT I rules, then validate whether each result is correct and applicable. Assign remediation through Settings Catalog, compliance policies, another security baseline, or an approved management channel. Test changes in a separate ring and watch for conflicts with existing policy.

Do not convert an audit result directly into a broad enforcement profile. A successful remediation needs both effective-setting evidence and a later audit result from the same device. Keep accepted deviations documented with owner, rationale, expiry, and compensating control.
