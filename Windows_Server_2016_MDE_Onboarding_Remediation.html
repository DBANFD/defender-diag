Repairing Defender onboarding on Server 2016

Field note covering a Microsoft Defender for Endpoint onboarding failure caused by Windows component store corruption on Windows Server 2016.

Identify the deployment-stage blocker

Scope: Server 2016 onboarding fails while enabling the Windows Defender feature. The recorded errors point to Windows component servicing; they do not prove that every onboarding prerequisite is otherwise healthy.

The original notes include deployment-tool exit 710, error 14081 / 0x3701, and 0x80073701. Microsoft documents 710 as failure to enable the Defender feature and lists a referenced-assembly problem as a known cause. Its guidance for that known issue is to open a Windows Server support case. See Windows Defender deployment tool troubleshooting.

Preserve the deployment output and the corresponding CBS and DISM logs before another attempt. Match timestamps and the failing operation. The historical notes are not a substitute for current logs.

Inspect before repairing

Run in elevated Windows PowerShell on the affected server. These checks do not install Defender or onboard the device. DISM diagnostics can take time.

Get-WindowsFeature -Name Windows-Defender
Get-Service -Name WinDefend, Sense -ErrorAction Continue
DISM.exe /Online /Cleanup-Image /CheckHealth
DISM.exe /Online /Cleanup-Image /ScanHealth

Retain C:\Windows\Logs\CBS\CBS.log and C:\Windows\Logs\DISM\dism.log. Check pending restarts and the applicable servicing stack and cumulative updates. Use Microsoft's Server Defender installation and update sequence to establish the supported baseline.

Repair with a suitable source

Plan a maintenance window and confirm recoverability for the server's roles. Where Windows Update is an allowed repair source, start with the normal repair path:

DISM.exe /Online /Cleanup-Image /RestoreHealth

Check the exit status and final DISM output before continuing. If policy or connectivity prevents downloading repair content, use an administrator-verified repair source. 0x800f081f means required source content was not found; it does not independently prove irreparable corruption.

For WIM media, first list the images, select the correct edition/index, and verify architecture, language, and servicing compatibility. The example path below is a placeholder for approved media:

DISM.exe /Get-WimInfo /WimFile:"E:\sources\install.wim"

An offline repair then uses /Source:wim:<path>:<verified-index>. Add /LimitAccess only when you intend to prevent Windows Update fallback. Older or unsuitable media can fail even when the file exists. Follow repair-source requirements and DISM repair guidance.

If repair succeeds, complete required restarts and reassess component health. If it fails, stop and investigate the new log evidence. Do not repeatedly inject guessed packages or treat an in-place upgrade as a guaranteed fix. Agree a supported repair or rebuild plan with Windows Server support.

Enable the feature, then retry onboarding

Only after servicing is healthy, use the supported Defender feature and update sequence. If installation is required:

Install-WindowsFeature -Name Windows-Defender

Check the result and restart requirement. Update the platform and security intelligence before retrying the current tenant's Server 2016 onboarding workflow. Obtain a fresh package from the Defender portal and follow its instructions. Do not assume an older deployment-tool command line or package format remains valid. See Onboard Windows servers.

Verify each layer separately

  1. Confirm the Defender feature reports installed and the installation has no outstanding restart.
  2. Check Get-MpComputerStatus for versions and the intended active or passive mode. The presence of WinDefend alone is insufficient.
  3. Check the MDE sensor and fresh portal reporting for the correct device.
  4. Verify assigned settings and any detection test required by your approved onboarding procedure.

If onboarding succeeds but antivirus remains disabled, continue with the antivirus-state investigation. Record repair and onboarding as separate outcomes. No successful repair is claimed for the historical case without its validation evidence.
