Targeted malware scans in Defender for Storage

Scope a storage scan to the objects under investigation and account for missed or failed scans.

What the update enables

Microsoft announced general availability of targeted on-demand malware scanning on 5 October 2026. Instead of scanning an entire storage account, investigations can target a blob or file, container or file share, or a path prefix. Defender for Cloud release notes.

This is useful when an investigation has a specific object to revisit. Write down the question first: retry a failed scan, examine a suspicious upload, or reassess a bounded set of stored objects.

Make the scope explicit

Targeting uses filters in the REST request body. Matching is case-sensitive; omitting filters scans the entire account. A filter matching nothing can still finish successfully with zero scanned items. Defender for Storage with on-upload scanning must be enabled, and the caller needs the documented scan permissions. Setup, request schema, and operating limits.

Before submitting a request, record the intended account, object paths, matching mode, and expected object count. Inspect the request as a whole, including its body. Confirm that an exact-object investigation has not accidentally become a prefix or account-wide operation.

Example: An investigation concerns uploads/review/sample.zip. An exact match targets that object. A prefix such as uploads/review/ represents a different scope and should be chosen deliberately.

Check cost and execution conditions

On-demand scanning is usage-based with no monthly cap. Filtered scan charges depend on data actually scanned; storage reads and other associated services can add cost. Only one on-demand scan can run per account, and cancellation is limited to early stages.

Agree a budget and a retry policy before automating scans. Avoid an immediate retry loop on every failed or delayed response. Preserve the scan identifier and reconcile its final state before deciding whether another submission is necessary.

Reconcile results with the question

  1. Capture the requested scope and scan start time.
  2. Monitor the scan to its final state and retain its summary.
  3. Compare scanned, skipped, and failed objects with the expected scope.
  4. Investigate a zero-object result as a possible path or scope mismatch.
  5. Route malicious findings through the incident process; record any containment action separately from the scan itself.

A completed request with no detection does not establish that every intended object was examined. Close the investigation only when the scan coverage and remaining gaps answer the original question. Keep evidence collection, malware detection, and remediation as separate steps in the record.
