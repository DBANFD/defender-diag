Know which identifier the next step requires

ValueMeaningUse carefully
displayNameA human-readable device nameUseful for finding candidates; do not assume uniqueness.
id / ObjectIdThe directory object identifierUse when the operation requires the directory object ID.
deviceId / DeviceIdThe device registration identifierKeep distinct from the object ID even though both are GUID-shaped.
MDE DeviceIdThe endpoint service identifierThis is a separate identifier in Defender hunting; do not substitute an Entra GUID.

Microsoft documents id and deviceId as separate properties of the Graph device resource. Check the target API or import template before selecting a column. A well-formed GUID is not proof that it identifies the intended device.

Prepare a minimal export

The tool accepts a local CSV with exactly these required field names: displayName, id, and deviceId. Additional columns are ignored. Obtain an authorized export and map its headers deliberately; exports from different portals may use different names.

If collecting with Microsoft Graph, its list-devices API requires the documented read permission and an appropriate signed-in role. Select only needed properties and retrieve all pages. The offline helper itself requires no Graph module or tenant connection. See List devices and permissions.

Save the following example as example-devices.csv to try the script:

displayName,id,deviceId
lab-win-01,11111111-1111-4111-8111-111111111111,22222222-2222-4222-8222-222222222222
lab-win-02,33333333-3333-4333-8333-333333333333,44444444-4444-4444-8444-444444444444
lab-win-02,55555555-5555-4555-8555-555555555555,66666666-6666-4666-8666-666666666666

These sample GUIDs have no operational meaning and must not be used for live changes.

Run the exact-name lookup

Download the offline PowerShell lookup · Inspect source

Use PowerShell 5.1 or later. The script reads the CSV and returns objects; it neither modifies the input nor changes any directory object or group.

.\Find-EntraDeviceId.ps1 -CsvPath .\example-devices.csv -Name 'lab-win-01','lab-win-02','lab-missing' |
    Format-Table RequestedName,Status,MatchCount,ObjectId,DeviceId

Matching trims surrounding whitespace and ignores case using an ordinal comparison. It does not use substring or wildcard matching, remove DNS suffixes, or silently choose a “newest” record. All matching rows are preserved.

Interpret the result before using an ID

StatusMeaningNext step
UniqueMatchOne exact name match with nonempty, parseable GUIDsVerify that this export record corresponds to the intended current endpoint.
AmbiguousMore than one matching row, including repeated identical rowsReview every candidate; no ID is automatically selected.
InvalidIdentifiersOne matching row but an identifier is missing, zero, or malformedRepair or recollect the source export; do not invent an ID.
NotFoundNo exact matching name in this CSVCheck spelling, export scope, header mapping, and collection time.

For ambiguous matches, inspect IdentifiersValid on each returned row as well. Empty input or missing required headers stops with an error instead of producing misleading matches.

With the example data above, expect one UniqueMatch for lab-win-01, two Ambiguous rows for lab-win-02, and one NotFound row. The duplicate must be investigated, not automatically deleted.

Reconcile candidates with current evidence

On a Windows Entra-joined or hybrid-joined device, dsregcmd /status exposes device registration details that can help compare the local DeviceId with the export's deviceId. Registered-device output differs; follow Microsoft’s dsregcmd interpretation for the relevant join state. Its output can contain identifying information and should stay in the authorized workspace.

Check the registration identity, join state, and collection time before using an object ID in another operation. A unique match in an old export is still only a unique match in that export. This tool intentionally performs no deletion, group assignment, or remediation.
